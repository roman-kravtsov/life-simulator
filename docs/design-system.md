# Design system

Birthright uses **React Aria Components** (Adobe, Apache-2.0) for the behaviour and accessibility of interactive controls, and our own **CSS Modules and tokens** for every pixel of the look. Chosen by Roman on 2026-10-24 after comparing React UI libraries (shadcn/ui, MUI, Mantine, Radix, Base UI and others). CSS Modules was kept over Tailwind because React Aria exposes state as data attributes that read naturally as plain CSS selectors, and our light and dark themes already live in CSS variables.

## Layers

1. **Tokens** (`src/styles.css`): colours, type, spacing, radius, focus ring, light and dark themes. Components use these variables and never raw colours or sizes.
2. **Kit** (`src/ui/kit/`): thin wrappers around React Aria Components with our styles. Screens import only from `src/ui/kit`.
3. **Screens** (`src/ui/*.tsx`): compose kit components and custom SVG. Text comes from `t(key)`; kit components take already-translated strings as props.

## Kit components

| Component | Wraps                    | Use                                                                                     |
| --------- | ------------------------ | --------------------------------------------------------------------------------------- |
| `Button`  | `Button`                 | All actions. `variant`: `primary`, `ghost` or `choice` (a full-width answer on a decision card; `aria-disabled` shows dashed); `icon` |
| `Switch`  | `Switch`                 | Settings: softer telling and skip quiet years (EVENT-006, TIME-002); US-prices line (MONEY-007) |
| `Stepper` | `NumberField`            | Placing the yearly focus points (UI-005): arrow keys on the field, minus and plus buttons for touch, an optional description tied to the field. `compact` hides the description from sight (it still names the field) and sets the control small; `note` is a short visible line under the control that is also tied to it |
| `Tabs`, `TabPanel` | `Tabs`, `TabList`, `Tab`, `TabPanel` | The life screen's tabs (UI-004, UI-010). `variant`: `underline` (the side columns) or `bar` (the fixed bar at the bottom of a phone). The list is always rendered first, before the panels, and takes a `label`. `forceMount` on a panel keeps it in the page while it is not selected (hidden, out of reach); arrow keys, Home and End move and select |
| `RadioGroup` | `RadioGroup`, `RadioField`, `RadioButton`, `Label`, `Text` | One choice from a few, all shown: the theme and the text size (UI-009). Takes a `label`, an optional `description` (tied to the group, and by React Aria to each radio too) and `options` with a `value`, a `label` and an optional `description` of their own. One tab stop; the arrow keys move and choose. Each option is a 2.75rem target, an empty ring that fills with a dot when chosen (a shape, not only a colour), styled by `[data-selected]`, `[data-hovered]`, `[data-pressed]` and `[data-focus-visible]`. Uses `RadioField` + `RadioButton`, as React Aria's `Radio` is deprecated |
| `Slider`  | `Slider`                 | Not used yet; kept for a later single-value setting                                      |
| `Tooltip` | `TooltipTrigger`         | Odds lens hints, if the lens ever needs them (UI-006)                                    |
| `Dialog`  | `DialogTrigger`, `Modal` | Information in a modal (UI-009); the whole journal and everyone in a large family (UI-004, UI-007). Its title is an `h2` (React Aria's dialog sets that level), so headings inside it are `h3`: the family groups, and in the life screen's Settings dialog the two parts (`SettingsPanel` and `DisplaySettings` take `headingLevel={3}` there and stay `h2` on the settings screen). Escape closes it and focus goes back to the button that opened it |
| `ConfirmDialog` | `DialogTrigger`, `Modal`, `Dialog` (`role="alertdialog"`) | Asks before something that cannot be undone: delete one life, delete all local data (SAVE-007). The cancel button has focus on opening, so Enter alone never confirms; confirming acts, then closes |
| `TextField` | `TextField`, `Label`, `Input`, `Text` | A labelled single-line field with a hint tied to the input (`description`): the epitaph and its characters left (DEATH-004), a journal line (UI-007). `labelStyle="prose"` sets the label as a line of the story (a reflection prompt that is the field's name); `inputRef` hands over the input, so a control elsewhere can send focus to it (the Journal button) |

`Stepper` renders React Aria's number field, which exposes a text input with a "Number field" role description (not `role="spinbutton"`); query it by role `textbox` and its label in tests.

## Tokens worth knowing

- `--ring-study`, `--ring-work`, `--ring-love`, `--ring-loss`, `--ring-illness`, `--ring-move`, `--ring-plain`: the growth-ring colours by theme (SUM-002), each with a light and a dark value. Each is at least 3:1 against `--paper` in its theme, and the patterns are drawn in `--paper`, so they show on every ring colour. Neighbouring rings differ by hue and by pattern, never by colour alone. Use them for the rings and their legend only.

- `--invalid`: the border of a field that is not valid (dashed as well as coloured), with a lighter value in dark mode.

## Screen patterns

- **Page and landmarks** (UI-010, `src/ui/Page.tsx`): every screen renders through `Page`, which gives `<>{header}<main id="content" tabIndex={-1} data-layout>…</main></>`. The header is a real `<header>` outside `<main>`, so it is the banner landmark without a role of its own; there is exactly one banner and one main on every screen, the ScreenBoundary fallback included. The skip link (in `App`) leads to `#content`, which takes focus without a ring. `data-layout="reading"` (the default) keeps the reading measure, with the page's padding; `"wide"` is the life screen's columns. `index.html` mounts the app on `<div id="root">`, a flex column at least as tall as the window, so the main fills what the header leaves. The life screen's header height and side-column width are tokens on `:root` (`--life-header-height`, `--life-side-width`), since the header is outside the main. Every screen but the life screen uses `SiteHeader` (`src/ui/SiteHeader.tsx`: the wordmark, the help link and the quick theme toggle), across the window at the same height as the life screen's header.
- **Start screen** (UI-002, `src/ui/StartScreen.tsx`): a title page. A still emblem of growth rings (decorative SVG, `aria-hidden`, coloured with the `--ring-*` tokens by class), the title and subtitle centred above the reading column, then the Continue card when a life is saved, the intro, the content note, the two switches of `SettingsPanel` and Begin a life, which is one press after the note. Past lives, Settings and Where the numbers come from are quiet buttons in a `<nav>` labelled "More", under a rule, with the privacy line last.
- **Birth screen** (UI-003, WORLD-008, `src/ui/BirthScreen.tsx`): the birth in prose (name and sex, place, the household's tenth and daily income, parents, and older brothers and sisters, which a first child is told plainly too), then a card "Where you were born" (an `h2` naming a region) with the same `CountryPanel` as the life screen's Country tab, each fact with its source and year and estimated values left out, then Begin this life and the seed. Under them, a quiet Back to the start: the life is already saved at birth, so the start screen offers to continue it.
- **Settings screen** (UI-009, `src/ui/SettingsScreen.tsx`): from the start screen's Settings button, an `h1` that takes focus and three parts with a rule between them: How you want to play (`SettingsPanel`, for the lives begun from now; a life in progress keeps its own, changed from its gear), How it looks (`DisplaySettings`) and What is stored on this device (`DeleteAllData`, the same words and dialog as on the past lives screen, with its own status region for a failure; on success the start screen says so). Back returns to the start.
- **Display preferences** (UI-009, UI-011, A11Y-004, A11Y-005): `src/ui/display.ts` keeps the theme, the text size and the motion choice in this browser, apart from any life, and puts them on `<html>` as `data-theme`, `data-text-size` and `data-motion`; no attribute means "follow the browser". `DisplaySettings` (`src/ui/DisplaySettings.tsx`) shows them as two `RadioGroup`s (System, Light, Dark; Default, Larger, Largest) and a "Reduce motion" `Switch` whose state is the player's choice or, without one, the system's; it is on the settings screen and in the life screen's settings dialog. The style sheet's side, all in `src/styles.css`: `data-text-size="large"` and `"larger"` set the root font size to 112.5% and 125%, on top of the browser's own size; `data-motion="reduced"` stops every animation, transition and smooth scroll, `"full"` allows them even when the system asks for less, and no attribute follows `prefers-reduced-motion`. That is one global rule set: components animate freely and never ask about reduced motion themselves (a test checks the module style sheets). "Delete all local data" resets the preferences too (`App` does it once the store says everything was deleted).
- **Text size and media queries**: everything is in rem or em, so it follows the text size. Media queries in em do not follow the game's setting: they are measured against the browser's own text size, so at "Largest" the layouts switch at the same window widths as at the default. The screens were checked at 125% at 400 px and 1440 px wide for sideways scroll and overlaps; the life screen's side columns may then need their scrolling safety net in a short window.
- **Money tab** (MONEY-002, MONEY-007): its lines (the international dollars note and, when on, the comparison with US prices) come before the switch, the panel's only control, so a keyboard player who reaches the switch has passed everything even when large text makes the panel scroll. The School & work and Country tabs have no controls and fit by keeping to short lines.
- **Life screen layout** (UI-004, UI-010, `src/ui/LifeScreen.tsx`): a sticky header (`LifeHeader`: wordmark, name, age and place, a settings dialog, the help link, Continue, and, on wide screens only, the Journal button and a strip of the life so far), and below it either three columns (900 px and up) or one column with a bar of tabs (below). The page scrolls as one; the side columns (`YouColumn`, `AroundColumn`, styled by `SideColumn.module.css`) are sticky, take their height from `--life-header-height` and the window, and every tab must fit a window 640 px tall (and 600 px) without scrolling: keep panels to short lines, one line a person, and put long text elsewhere. `overflow-y: auto` on a panel is the safety net, not the plan. The story is first in the page, then You, then Around you; CSS grid places them. The narrow layout is chosen by `useNarrow` (a `matchMedia` hook) and renders the three parts as force-mounted `TabPanel`s. While a decision waits, Continue stays on the page, `aria-disabled`, with the reason tied to it. The plan is a tray (`PlanWidget`): docked at the foot of the window above 1300 px wide and 700 px tall, and an ordinary block between this year and the earlier years below that (and in the narrow layout); the scroll padding in `styles.css` follows each mode. When docked it is visually last but comes before the earlier years in the tab order (it is before them in the markup), so Tab reaches the plan before the earlier-years links, by design. Sizes that depend on text are in em or rem (the side columns are `min(18rem, 28vw)`), so larger text does not push the story off the page. `LifePanels.tsx` holds the content of each tab as plain terms and lists.
- **Reflection prompt** (UI-007, `src/ui/LifeScreen.tsx`, `src/ui/Journal.tsx`): after the year's events (the live region is elsewhere, see **One live region**), when the store offers a prompt for the year just lived (never while a decision waits, nor after death). A section labelled by its eyebrow "A pause", set off by a rule, then one `JournalLine`: the prompt's words are the field's label, set as prose (`labelStyle="prose"`), so a screen reader hears the question as the field's name, then the characters left as its description; a single-line field (at most `JOURNAL_MAX_LENGTH`, 200), Save, and a polite paragraph beside Save that says "Your line is saved.", "Your line was removed." (saved empty) or "There is nothing to save." It is never required and nothing nags: Continue does not wait for it. Focus stays where the player put it (the field after Enter, Save after a press). Lines being written live in the life screen (`drafts`, by prompt id, for the current age only), so a new snapshot of the same year or a tab left and come back to keeps them. Continue and Back to start first save every draft that is not empty (with its prompt id, or none for the player's own line), so nothing typed is lost, even in the year the person dies (a finished life takes no more lines); the next year starts empty.
- **Notes tab** (UI-004, UI-007, `NotesPanel` in `src/ui/Journal.tsx`): a `JournalLine` "A line for this year" (the player's own line for this age, no prompt), then "Latest lines": the three newest, newest first, one row each with the age in a narrow gutter and, for a line that answered a prompt, the prompt's words small above it (looked up with `promptTextKey` from the store and guarded with `hasString`, since a saved life may name a prompt this version lacks). In the wide side column each row is cut short by CSS with the whole text in its `title`; in the narrow layout, where the column is the page's width and scrolls with it, the lines are whole; the button under them ("All {n} lines", or "Read the line in full" for one) opens a `Dialog` with the whole journal, newest first, scrolling inside the dialog, so a line cut short is always reachable by keyboard. With nothing written, one short line says so. The Journal button in the wide header opens this tab and sends focus to its field each time it is pressed. The tab fits a 600 px tall window with three lines of the longest length (`e2e/loop.spec.ts` checks it).
- **A large family** (UI-004, `FamilyPanel` in `src/ui/LifePanels.tsx`): the Family tab lists eight people at most across parents, brothers and sisters, and others. When there are more, the living are kept first (then the groups' order), each group keeps its heading (the siblings heading still counts all the living brothers and sisters), and a button "And {n} more people" (plural-safe) opens a `Dialog`, "Everyone in your life", with everyone in the same groups and no cap. So the tab fits by construction rather than by scrolling.
- **Stats that moved** (A11Y-002): when a stat moved by 3 points or more over the step just taken (the store's `statChanges`), the screen's one live region ends with a paragraph, "Health rose by 4. Happiness fell by 3." (stat names from `life.stat.*`, plural-safe keys `life.statChange.rose|fell.*`). Nothing is said when nothing moved by much or while a decision waits; the bars in the You column show the same to the eye.
- **Decision card** (UI-006, `src/ui/DecisionCardView.tsx`): a labelled region with an `h2` that takes focus when the card appears, the event text, then one `choice` button per choice. A locked choice keeps `aria-disabled` (still focusable) and its reason, cost and odds lens sit in a block tied to the button with `aria-describedby`. Odds are always words (`oddsWords` in `src/ui/words.ts`), money goes through `formatMoney`.
- **Plan widget** (UI-005, `src/ui/PlanWidget.tsx`): controlled by the life screen, which sends a plan with Continue only when the player changed it (`planToSend` in the store). Forced points and locked areas are said in words.
- **Help** (UI-012, `src/ui/HelpNote.tsx`): `HelpNote` follows any event, decision or condition with a help topic; `HelpLink` opens the directory in a new tab with `rel="noopener noreferrer"` and a screen-reader hint. The header carries an always-available "Need to talk?" link.
- **Summary** (SUM-001, `src/ui/SummaryScreen.tsx`): the h1 is the person's name and takes focus. Then the closing passage, the years against the life expectancy (DEATH-003), the rings, the key moments, what shaped the life, the life in brief, the last year's events, the player's notes (SUM-005), the epitaph and the seed. No score and no rank; lines that do not apply to a short life are left out rather than answered with "none". `EventLine` (`src/ui/EventLine.tsx`) is shared with the life screen.
- **Rings** (SUM-002, `src/ui/Rings.tsx`, geometry in `src/ui/ringsLayout.ts`): plain SVG in a 100 by 100 view box, one ring a year, the oldest innermost, each as wide as its thickness (happiness). Every theme has its own pattern as well as its colour (dots, diagonals, cross-hatch, horizontal lines, vertical lines, waves, solid), a legend names the themes that occur, and a closed `<details>` "Year by year" holds a real table with the same facts. Numbered marks sit on the years of the key moments, spread round the circle by the golden angle; a badge that has no room on a very narrow ring near the centre moves out with a line back to its ring. The numbers are the numbers of the list of moments. The rings are as wide as the square root of their thickness (so the thinnest of a hundred stay visible), and the pattern tile shrinks from 2.4 to about 0.9 view box units as the life passes 10 to 60 rings. The rings grow in with CSS only (timers are banned in `src/`), and the page's motion rules stop that when motion is not wanted. `RingsThumb` draws the same layout small, with thinner lines of paper between rings for a long life so the picture is not washed out.
- **Summary notes** (SUM-005, `src/ui/SummaryScreen.tsx`): just before the epitaph, a section "Your notes" with every journal line in the order of the years (`JournalEntries`, the same rows as the Notes tab but with the whole text): the age, the prompt's words small above a line that answered one (guarded), then the line. Shown only when the life has lines; an archived summary from before the journal has no `journal` field and shows nothing. The epitaph keeps its place.
- **Epitaph** (DEATH-004, `src/ui/Epitaph.tsx`): a `TextField` with the characters left as its description and a Save button, then the words as a blockquote with Edit. Saving is announced in a polite paragraph, and focus goes to the Edit button, never to the page.
- **Resume card** (SAVE-002, `src/ui/StartScreen.tsx`): "Continue your life" with the name, age and place, a primary Continue and a note that a new life replaces it. A save that cannot be opened is a calm `role="note"` with "Discard it".
- **Past lives** (SAVE-003, SAVE-007, UI-008, `src/ui/PastLivesScreen.tsx`): one card a life, with its growth rings in small (`RingsThumb` from the rings in brief the archive keeps, decorative and `aria-hidden`), the name as an `h2`, the line about the life, the epitaph and the date, then Open and Delete (a `ConfirmDialog`) at the foot of the card. From 900 px (56.25em) the screen reaches past the reading measure (at most 56rem, centred on it) and the cards go two across; below, one column. "Delete all local data" (`DeleteAllData`) has its own `ConfirmDialog` that says what goes. Focus returns to the heading when a life is deleted, because its button is gone. Back to start is last.
- **Disclosure**: native `<details>`/`<summary>` is allowed for disclosure (the year-by-year table, how the shares are worked out), because the browser gives it the open/closed state and keyboard behaviour for free. Give it the global `disclosure` class (in `src/styles.css`) for the marker and a 2.75rem target.
- **Screens that show stored lives** (life, summary, past lives) are wrapped in `ScreenBoundary` (`src/ui/ScreenBoundary.tsx`), keyed by screen: a life saved by another version may name text this one lacks, so lines are left out with `tryT`/`hasString` rather than thrown over, and if a screen still cannot be shown it says so calmly with a Back to start button.
- **Destructive results are announced**: the past-lives screen's one `role="status"` says "The life of {name} was deleted."; after "Delete all local data" the start screen's status region says so, and its words arrive after the region is on the page (`useDeferredValue` with an empty first value).
- **Notes about storage**: a save that fails mid-life, or an archive that cannot keep a life, is said in a `role="note"` inside an `aria-live="polite"` container that is on the page before the words arrive, so it is announced once; notes about a resumed life are plain `role="note"`.
- **One live region** (`role="status"`) per life screen. It is a visually hidden region placed in the main before the columns or the tabs, in both layouts, so it is never inside a part a phone hides (a hidden, inert tab panel is not announced). It is on the page from the first render and carries, in plain lines, what the year tells: the quiet-years line, "A decision is waiting." or the year's line, each event in words (`eventWords`: text, the choice and what came of it, the data note, the help line) or "A quiet year.", and the stats that moved. Its contents are keyed by the number of years lived and whether a decision waits, so a year told in the same words as the one before is new nodes and is said again. The visible story shows the same and is not live, so nothing is read twice. Elsewhere on the life screen, new status-like text elsewhere uses `aria-live="polite"` on a paragraph instead of a second status region (the journal's saved note, the epitaph's).
- **Keyboard play** (A11Y-001): `e2e/keyboard.spec.ts` plays a whole life at 400 px and 1440 px with key presses only (Tab and Shift+Tab to reach a control, Enter, arrow keys, Home and End in tab lists, Escape for dialogs), checks that focus lands on each new screen's heading and that the focused control shows a ring. Continue is in the header, so Shift+Tab from the year's heading reaches it; on a phone the bar of tabs comes first.
- `.eyebrow` (in `src/styles.css`) is the small uppercase label above a section; a screen's module sets its own margin.
- `.visually-hidden` (in `src/styles.css`) is for text only screen readers need.

## Rules for adding or changing a component

- Style states with data attributes: `[data-pressed]`, `[data-hovered]`, `[data-focus-visible]`, `[data-selected]`, `[data-disabled]`.
- Keep a 2.75rem minimum touch target and the shared `--focus` ring.
- Animate freely: the global rules in `src/styles.css` hold motion back when the player or the system asks. Do not write `prefers-reduced-motion` queries in a module.
- Add a test in `tests/ui/kit.test.tsx` that uses the keyboard, not only the mouse.
- Import React Aria sub-paths by named import from `react-aria-components` inside the kit only, to keep bundles tree-shakeable.
